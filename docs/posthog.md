# Work site analytics

PostHog replaces Vercel Web Analytics. Hosting remains on Vercel. The existing US project is 608995. No person profiles, identify calls, autocapture, replay, heatmaps, performance/error capture, surveys, feature-flag requests, or persistent analytics cookies/local storage are enabled. Session storage is required; unavailable storage disables analytics.

Vercel configuration: NEXT_PUBLIC_POSTHOG_KEY and NEXT_PUBLIC_POSTHOG_HOST (https://us.i.posthog.com), with system NEXT_PUBLIC_VERCEL_ENV. Only the production environment on work.thearcades.me collects production events. Preview collection requires NEXT_PUBLIC_POSTHOG_PREVIEW_ENABLED=true and a .vercel.app hostname. The verification branch alone enables this switch.

One pageview is emitted per committed pathname change, including the initial page; fragments and query-only changes do not count as another page. Case-study views follow pageviews. Entry campaigns and referring domain persist in session storage across reloads. Clicks retain public placement; no destination addresses are captured. before_send replaces SDK properties with an allowlist. Raw URLs, referrer paths/queries, form data, arbitrary properties and person updates are dropped; native URL properties are reconstructed from the allowed public host/path and referring domain. Session and random pseudonymous identifiers support same-session analysis. The SDK-provided raw browser user agent (`$raw_user_agent`) is retained as an event-only field so PostHog can classify ordinary browser traffic versus known bots and automation. IP-based geolocation remains disabled and the event IP property stays zeroed. PostHog still receives transport connection information. Dashboard descriptions must disclose retained raw user agent data; do not describe these events as anonymous or as excluding all browser metadata.

Dashboard: [Work site — raw traffic and intent](https://us.posthog.com/project/608995/dashboard/2095308). Every production report must filter hostname=work.thearcades.me and environment=production, and exclude utm_campaign=analytics-verification. Reports: pageviews by referring_domain; pageviews by landing_page; campaigns by utm_campaign; case_study_view by slug; resume_click/contact_click/booking_click by placement; a same-session pageview → case_study_view → contact_click or booking_click funnel; and session paths. For post-fix events, PostHog's virtual traffic classification can separate regular browser traffic from user-agent-detectable bots and automation; IP-only bot signals remain unavailable by design. Historical work-site events captured before this fix have no raw user agent and remain classified as automation, so do not retroactively reinterpret them. Treat `$virt_traffic_type=Regular` as human-like browser traffic, not proof of a unique human. Clicks measure intent, not completed inquiries/bookings. Confirmed hiring inquiries and booked conversations are entered with a private evidence reference in `/jobs/review` and counted separately by week. An open week does not establish zero. Do not report returning visitors or cross-site journeys. See [the funnel scorecard](./funnel-scorecard.md) for the 14-day comparison, professional handoff source filters, privacy-safe signup counts, and separately reviewed inquiry outcomes.

Configuration reference: https://posthog.com/docs/libraries/js/config and https://posthog.com/docs/libraries/next-js. Verification must distinguish payload tests, received preview events, received production events, and saved/rendered dashboard reports. Deployment alone does not establish receipt.

## Report date-window contract

Use one explicit UTC interval, `start_utc <= timestamp < end_utc`, for every tile in a report. Record both bounds and the export time. Daily and weekly buckets use UTC; an incomplete current day/week is labelled partial. Dashboard date controls alone are insufficient evidence for saved HogQL tiles: each saved query must apply the same resolved bounds, production filters, verification exclusion, and selected traffic cohort. Remove independent rolling windows such as a tile-local `now() - interval 30 day` when the dashboard is displaying a different period. Verify the saved query and rendered tile after changing the dashboard window.

Raw traffic and `$virt_traffic_type=Regular` reports use different cohorts and must be labelled separately. Do not divide a Regular-only intent numerator by an all-traffic denominator. Use the scorecard's complete UTC calendar-day windows for pre/post comparisons and keep manually confirmed outcomes separate from browser intent.

Apply `db/migrations/0007_work_site_outcomes.sql` to the private Neon database before deploying the confirmed-outcomes form. Its entries are private, require a manual evidence reference, and are never sent as PostHog events. This migration was applied to production on September 27, 2026.
